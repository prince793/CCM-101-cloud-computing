# 💭 Mission Reflection — Checkpoint 8

Completing this Multi-Cloud Explorer mission gave me a much clearer picture of how AWS, Azure, and GCP actually differ, beyond just reading about them in theory. Of the three, Google Cloud Platform impressed me the most because of how strong it is in AI/ML and Kubernetes — knowing that Google itself created Kubernetes made its dominance in that space make a lot of sense.

At the same time, researching all three platforms showed me how much they actually have in common. Every provider offers the same basic building blocks — a virtual machine service, an object storage service, an identity/access management system, and managed databases — just under different names (e.g., EC2 vs. Azure VMs vs. Compute Engine). Once I understood that pattern, comparing them became a lot easier.

Working on the client recommendation scenarios really drove home how much business context matters when picking a cloud provider. A cash-strapped startup needing to scale fast has very different priorities from a university that's already built around Microsoft tools, or an AI company that needs GPU/TPU power. There's no single "best" cloud platform — the right answer always depends on the client's existing environment, budget, and technical needs.

As part of this "Cloud Evaluation Team" exercise, I also got hands-on practice with basic Linux system administration by using a KillerCoda playground to inspect a server's OS, CPU, memory, and disk space using commands like `uname -a`, `lscpu`, `free -h`, and `df -h`. It helped me connect the dots between a physical/virtual server's specs and which cloud VM tier would actually be a good fit for hosting it.

Overall, this lab pushed my GitHub portfolio a step further — instead of just having code projects, I now have a documented, well-organized case study that shows I can research, compare, and make recommendations across multiple cloud providers, which is a skill directly relevant to real IT and cloud consulting work.
